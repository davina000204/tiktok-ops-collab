一、系统定位

本工作台负责把 TikTok 达人样品申请、审核、寄样、内容交付、Code 回收、商家 Code 交付和飞书分品牌同步集中到一套流程中。

核心原则：达人用户名 + 商品 PID 是唯一键；支持多条视频、vid 和 Code；未发布内容单独分类；异常必须核实。

四、每日标准操作 SOP

1. 开始工作

  1. 打开 Chrome，确认只保留一个 TikTok 样品管理固定页。
  2. 打开工作台，查看 TikTok 快照和飞书同步状态。
  3. 快照在 15 分钟内表示数据新鲜；否则等待补查或刷新样品页。

2. 处理今日待办

依次处理：待审核 / 待补全、待索要 Code、Code 待发商家、数据异常。点击卡片右侧按钮可直接进入队列。

3. 审核样品申请

  1. 检查达人、品牌、商品 PID、SKU、库存和剩余时间。
  2. 待审核行只显示“通过”和“拒绝”两个决策按钮。
  3. 完整则通过；不合格则拒绝；缺资料则进入补齐流程。
  4. 多条待审核可勾选后批量通过或批量拒绝。

4. 寄样与内容交付

待发货表示等待寄样；已发货和内容处理中表示等待达人发布。系统同步后自动进入已完成或未发布视频分类。

5. 履约期与 Code 跟进

  1. 内容处理中可点击“14 天履约提醒”，生成印尼语和中文双语可编辑话术。
  2. 话术用于提醒达人在收到样品后 14 天内完成并上传视频。
  3. 已完成记录没有 Code 时，状态列显示“待添加 Code”。
  4. 进入“视频与 Code 跟进”。
  5. 勾选达人后一键复制 Code 话术。
  6. 系统自动标记 Code 已请求。
  7. 达人返回 Code 后录入，记录进入商家 Code 交付，可一键复制给商家。

6. 多条视频处理

打开编辑记录，点击“添加视频”，每条分别填写链接、vid 和 Code。新版本会完整保留全部内容。

7. 商家 Code 交付

单条点击“一键复制”，或点击“一键复制全部”。内容只包含达人名称、视频链接和 Code。发送给商家用于投流，不判断商家是否实际完成投放。

8. 结束工作

复制今日简报，确认飞书无错误，然后可以关闭 Chrome 或让电脑睡眠。下次打开会补齐数据。

六、异常处理

  • 缺少达人用户名或商品 PID
  • 已完成但没有视频链接或 vid
  • Code 状态已收到但 Code 为空
  • 品牌映射不存在
  • OCR 识别待核实
异常记录必须回到 TikTok 原页面核实，不能直接通过、拒绝或同步商家。

七、飞书同步

  • 按品牌分表，不写入统一总表。
  • 商品 PID 必须映射到品牌。
  • 同一达人 + 商品 PID 只保留一条。
  • 视频链接、vid 和 Code 支持多行。
  • 同步失败会显示在首页“飞书同步”状态。

八、数据时效与关机策略

电脑关闭时不会读取 TikTok 新数据，但已有数据不会丢失；重新打开后执行全量补查。真正的 24/7 实时更新需要 TikTok 开放样品、审批、活动和消息 API，并重新授权店铺。

开放后需要的权限包括：Read/Manage Seller Affiliate Collaboration、Read/Manage Affiliate Partner Campaigns、Manage Affiliate Messages、Affiliate Information、追踪链接和商品推广链接权限。

九、每日检查清单

  • 只保留一个 TikTok 样品管理固定页
  • 工作台 TikTok 快照时间正常
  • 飞书同步无报错
  • 待审核队列已处理
  • 异常队列已核实
  • 已完成视频已索要 Code
  • Code 已一键复制给商家
  • 今日简报已复制

十、故障排查

工作台没有新数据

  1. 检查 TikTok 样品页是否打开。
  2. 检查 Chrome 扩展是否启用。
  3. 刷新样品页后等待 1 分钟。
  4. 查看扩展错误提示。

飞书没有更新

  1. 查看首页飞书同步状态。
  2. 检查商品 PID 品牌映射。
  3. 检查 Supabase 云端函数 feishu-sync 和飞书授权。
  4. 重新同步后核对品牌表。

十一、AI 使用边界

AI 可做 数据分类、品牌匹配、异常识别、话术、今日简报、重复检查。

必须人工确认 批量拒绝、对外高风险消息、预算投放、修改活动规则、删除业务数据。
